# 内容独立与自动静态构建方案

## 目标
保留原 GitHub Pages 网址、现有紫色校园界面、资料分类、搜索、在线阅读和反馈入口。以后只维护资料文件与文字信息，不编辑生成后的页面。

## 推荐架构
按用户后续确认，接入 VitePress 静态站点生成器及自定义主题；原 Node 生成器仅作为现有首页与 PDF 阅读布局的兼容适配器。网站代码仓库仍为 TBB592/gcsx，新增公开内容仓库 TBB592/gcsx-content，存放当前三份 PDF、内容清单、后续 Markdown 指南和维护说明。公开内容仅迁入目前已公开资料，不扫描或自动公开其他学习文件。

网站仓库存放生成器、页面模板、样式和前端脚本。构建输出为独立目录，通过 GitHub Actions 上传 Pages artifact 发布，生成的网页和预览不再需要人工编辑。保留原 HTML 阅读地址、PDF 下载路径和 counter.html 地址。历史提交不重写。

## 日常维护
替换 PDF 保持原文件路径即可；新增资料添加一个清单项，填写名称、类别、简介和文件路径。支持课程学习、选课指引、校园生活。文字指南支持 Markdown，按白名单规则渲染，不执行嵌入脚本。构建自动生成卡片、分类数量、搜索字段和阅读页面。

## 自动发布触发
网站代码更新时运行构建。为了不要求用户创建跨仓库写入令牌，网站工作流定期检查内容仓库的提交版本（每小时，GitHub 调度可能延迟），发现变化才重新部署；同时提供手动运行入口。内容更新不是保证即时上线。后续若需要即时跨仓库推送触发，可单独配置精确授权机制。

## 构建与可靠性
构建时拉取固定内容提交，使用 Poppler 生成预览，校验清单、路径边界、重复标识、PDF 页数与图片完整性。缓存按 PDF 内容哈希区分，未变化文件复用预览。站点构建只读取自己生成的资料目录，清理已删除或缩短资料的旧预览。图片/PDF 使用版本标记避免旧缓存。

失败时不发布不完整结果，线上保留上一个成功部署。工作流按单一部署队列运行，避免并发发布旧版本。内容仓库独立说明上传、替换、分类与查看发布状态的方法。

## 迁移与验证
先准备内容仓库、构建输出和维护说明，再测试三份现有资料、搜索、分类、页码跳转、Markdown 渲染及手机布局。核对下载文件哈希、路径兼容和计数地址，然后切换 Pages 到 Actions 发布，确认公开网页正常。记录切换前提交与 Pages 配置，支持回退。

## 其他方案
1. 已采用：VitePress + 现有布局适配器，保留视觉与链接。
2. 备选：仅完善原生成器；用户希望使用成熟 SSG，未采用。
3. 仅移动 PDF，不配置构建：工作量较少，但仍需手动生成发布，不满足维护目标。
